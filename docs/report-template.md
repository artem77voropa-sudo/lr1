## 2. Змінений маршрут

Маршрут починається у браузері, де користувач натискає кнопку Показати підсумок. JavaScript надсилає запит через apiFetch('/api/incidents/severity-summary'). У файлі IncidentEndpoints.cs цей запит приймається ендпоінтом GetSeveritySummaryAsync, який звертається до IncidentQueries.cs. Там виконується LINQ-запит з групуванням _dbContext.Incidents.AsNoTracking().GroupBy(i => i.Severity).Select(...).
Далі EF Core транслює цей запит у SQL: SELECT i.severity, COUNT(*)::INT FROM incidents AS i GROUP BY i.severity та виконує його в PostgreSQL. Отримані дані пакуються в DTO IncidentSeveritySummaryResponse, додаються нульові значення для відсутніх категорій і повертаються як JSON із кодом 200 OK. На фронтенді функція з app.js отримує масив і через textContent безпечно вставляє елементи в DOM-дерево (#severity-summary-list).

## 3. Виконані зміни

У контрактах IncidentResponses.cs додано новий запис DTO IncidentSeveritySummaryResponse(string Severity, int Count) для передачі агрегованих даних. У файлі IncidentQueries.cs реалізовано асинхронний метод GetSeveritySummaryAsync з AsNoTracking() та сформовано сталий список усіх рівнів критичності із заповненням нулями для порожніх груп.

У файлі IncidentEndpoints.cs замінено тимчасову заглушку 501 NotImplemented на реальний виклик queries.GetSeveritySummaryAsync(...) із поверненням Results.Ok(summary). У файлах index.html та app.js додано розмітку панелі підсумку, кнопку, стан завантаження та безпечний рендеринг списку через textContent.

## 5. Security-сценарій

Гіпотеза полягала у перевірці можливості виконання Stored XSS через поле Description інциденту. У стані до в базу даних було додано запис із шкідливим вмістом, який містив HTML-тег script. Для перевірки було зроблено запит, що повертає цей тег у текстовому полі JSON.
Під час спостереження виявлено, що браузер відображає рядок як звичайний текст і не виконує код. Першопричина полягає у використанні безпечного DOM API (textContent та createTextNode) замість innerHTML у app.js. Це забезпечує виправлення та захист на рівні фронтенду. Повторна перевірка підтвердила, що теги відображаються як буквальний текст, позитивна регресія відсутня (інтерфейс працює стабільно), а залишковий ризик полягає у необхідності дотримуватися цього правила при додаванні нових блоків UI у майбутньому.
